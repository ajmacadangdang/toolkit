Prompt 1 — Create the resource

Act as an instructional designer and web developer. WHO: Faculty in [COLLEGE OR DISCIPLINE] teaching [COURSE OR TOPIC] in face-to-face or online settings. WHAT: Create a short, interactive faculty development handout featuring three active learning strategies: Think–Pair–Share, Case-Based Learning, and One-Minute Paper. HOW: For each strategy, include a simple explanation, a relevant teaching example, and a clickable tip or reflection question faculty can apply to their course. REQUIREMENTS: Make it clear, responsive, and accessible following applicable WCAG 2.1 Level AA criteria. Include readable text, sufficient contrast, and keyboard-operable interactions. Generate one standalone HTML file with embedded CSS and JavaScript, no external libraries. Explain how to save and open it. Flag items for faculty review and accessibility testing.

Example WHO: Faculty in the College of Engineering teaching Introduction to Materials Science; or faculty in the College of Veterinary Medicine teaching Clinical Reasoning. Keep the example grounded in an actual course.

Prompt 2 — Make one improvement

Improve the interactive handout by [DESCRIBE ONE CHANGE]. Keep the existing content and working features. Explain what changed and return the complete updated HTML file. Identify what I should manually test before sharing.
Reminder: Use approved tools and institutionally permitted information. Never input restricted student, faculty, patient, or other sensitive data without authorization.

What makes interactive learning effective?

Interactivity matters when it helps learners think, practice, receive feedback, and apply what they learn—not simply click through content. Use these research-informed principles to review an AI-generated prototype.

For our faculty handout: Opening a strategy card helps faculty find information. Asking faculty to choose a strategy for a realistic teaching challenge, explain the choice, and receive feedback offers a richer opportunity to practice applying it.

Keep exploring after the workshop

The faculty handout is only one starting point. Bring a real teaching challenge to a faculty subject-matter expert and create a resource that solves it. The strongest next project is not necessarily the most interactive—it is the one faculty and learners actually need.

Use case 01

Interactive study guide

Work with a faculty member to identify topics students find difficult. Turn approved concepts into short practice questions, worked examples, and explanatory feedback.

Faculty validates: key concepts, answer rationale, accuracy, and common misconceptions.

Use case 02

Short self-paced module

Co-design a concise module to introduce a concept, give learners practice, and check understanding at their own pace.

Faculty validates: learning outcome, sequence, examples, and assessment decisions.

Use case 03

Something else useful

Create a case-based decision activity, quick reference tool, practice simulation, or faculty development resource based on the real learning need.

Together decide: whether an interactive format is the right solution.

A simple faculty + ID collaboration cycle

  1. Listen: Ask faculty what learners struggle with and what success would look like.
  2. Co-design: Agree on one learning outcome, source material, a small interaction, and the feedback learners need.
  3. Prototype: Use NaviGator Chat to draft a small activity using only approved, non-sensitive materials.
  4. Review together: Faculty checks disciplinary accuracy and authenticity; the instructional designer checks alignment, UX, and accessibility.
  5. Test and refine: Check keyboard operation, content accuracy, and the learner experience; revise before deployment.
  6. Share and learn: Publish through an approved channel, disclose AI assistance accurately, and collect useful feedback or learning evidence.

From HTML to SCORM in Canvas

Your standalone HTML prototype can become a SCORM learning resource when your LMS needs to launch the experience and, if appropriate, track completion or scores. SCORM is one option—not a requirement for every faculty handout.

Advanced AI models may generate a ready-to-upload SCORM ZIP file directly. That can save packaging steps, but it does not guarantee a valid package. Always inspect, validate, and test the ZIP in Canvas before sharing it with faculty or students.
01 • Prepare

Start with working HTML

Confirm that your interactive resource opens in a browser, uses approved content, and works with keyboard navigation. Decide whether you need ungraded access, completion tracking, or a score.

02 • Request

Ask AI to create the SCORM files

Use the prompt below. Ask for a downloadable SCORM 1.2 ZIP when the model supports file creation. Otherwise request every file and step-by-step packaging instructions.

03 • Package

Check the ZIP structure

A SCORM package needs an imsmanifest.xml at the ZIP root, a valid launch file, referenced assets, and runtime communication where tracking is required. Zip the contents of the package folder—not an extra parent folder.

04 • Upload and test

Import into Canvas

In a Canvas course with SCORM enabled, open SCORM, upload the ZIP, and choose the appropriate import type (such as a page or assignment). Launch it, test controls and accessibility, and verify any completion or score reporting.

Copyable SCORM packaging prompt

Act as an instructional designer and SCORM developer. I have a working HTML learning activity and want to deploy it in Canvas. WHAT: Create a valid SCORM 1.2 package using my existing activity. Preserve its content, styling, interactions, and accessibility features. TRACKING: [Choose: ungraded resource / report completion / report score]. If tracking is needed, use the appropriate SCORM runtime calls and clearly explain the completion condition. OUTPUT: If you can create downloadable files, provide one ready-to-test SCORM ZIP. Otherwise, provide all required files (including imsmanifest.xml and any runtime JavaScript) plus clear Mac-friendly instructions for organizing the files and zipping them correctly. TESTING: Give me a short checklist to validate the ZIP, upload it through Canvas SCORM, check launch and navigation, and verify completion or scores. Do not claim the package works until it is tested in Canvas.

Before submitting the prompt, attach or paste your actual HTML and any supporting assets. Remove private, restricted, patient, or student data unless explicitly authorized for the tool.

How to ZIP the package on a Mac
  1. Create a folder for the generated SCORM files and place imsmanifest.xml, the launch HTML file, scripts, and assets inside it.
  2. Open the folder and confirm imsmanifest.xml is at the same level as the launch file, not nested in another folder.
  3. Select the files and asset folders inside that folder, Control-click, and choose Compress.
  4. Rename the resulting ZIP clearly, such as active-learning-scorm12.zip.
  5. Open the ZIP to inspect its structure before uploading. Do not simply rename an ordinary HTML ZIP to SCORM.

Three quick checks for your HTML prototype

  1. Keyboard: Can you reach and activate each control using Tab, Shift+Tab, Enter, and Space? Is focus visible?
  2. Clarity: Are headings descriptive, instructions clear, and important information understandable without depending on color alone?
  3. Feedback: After interacting, can you perceive the result? For a fuller review, verify dynamic feedback with a screen reader.

These are introductory checks, not a complete accessibility evaluation. Automated accessibility scores and AI-generated claims are not proof of WCAG conformance.

Need the technical standards? (Optional)

For detailed reviews, consult the official WCAG 2.1 standard (new tab) and the W3C Easy Checks guide (new tab). UF's ADA and Title II accessibility page (new tab) provides university context and training links.

Before sharing with faculty or students: Have a subject-matter expert review content and examples, perform accessibility and functional testing, confirm the hosting method works, and make sure AI disclosure describes the actual workflow.
